# Agent Note: 产品模型连接

Status: implemented

[English](2026-10-20-model-connections.md) | 中文

## 问题

用户拥有的 API 连接具有身份、凭据、模型选择和更新规则，这些内容应独立于插件配置结构的变化而持久保存。MaaS 端点可能通过同一账号和基础地址提供 Chat Completions 与 Responses 模型。

## 决策

model-connections 服务通过现有领域 KV 存储管理一个带修订号的聚合，凭据仍由凭据提供方保存。已提交记录编译为稳定的 pi-ai adapter 注册，Cordis 管理服务组合与卸载。默认模型服务接受一个可撤销的来源，产品默认值不存在时保留配置回退。

内置模型提示是静态应用数据。模型显式协议优先；省略协议时采用内置精确 ID 对应的协议，未知 ID 默认使用 Chat Completions。保存时写入该选择。启动和选模均不获取公开目录。在线发现由用户针对已保存端点显式发起，不自动采纳候选。

即使模型采用不同协议，每个连接仍保持单一提供方身份。协议序列化、工具流、用量、取消与请求准备继续由现有 pi-ai adapter 处理。产品代码使用其公开编译器与运行时工厂，不导入内部实现。

## 考虑过的方案

**将 Cordis 配置作为连接存储。** 外观接口可以隐藏命名空间，但仍保留产品记录与插件配置之间的耦合。产品领域由单一写入者管理，不双写这些设置。

**重设计关系型存储。** 现有 KV 抽象足以承载首版连接聚合。替换整个应用持久化会超出模型接入范围，也无法提供跨秘密存储与运行时注册的事务。

**每种协议建立独立提供方路由。** 这会把内部协议划分暴露给默认模型与持久化会话引用。根据模型解析后的协议分派请求，可以保留连接的稳定身份。

## 影响

持久化先于运行时发布。激活失败与持久保存分别可见；保留的连接可以沿用旧设置，已删除或停用的路由则会撤下。已替换的凭据引用继续供已准备的请求使用，不自动回收。

首版服务限定单运行实例的所有者，不提供共享进程用户隔离，也不承担云端计费、路由、账号联邦、凭据加密或自动数据迁移。Stage 不拥有 MaaS 数据。
